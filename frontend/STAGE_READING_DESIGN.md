# Five life stages, one handbook

This document records the design at the time of the five-stage migration. See the [shared README](../frontend/README.md) for the current layout, [acceptance report](../frontend/ACCEPTANCE.md) for the migration results and [navigation design](../frontend/NAVIGATION_DESIGN.en.md) for the subsequent review.

**Design decision.** Selecting a life stage answers “What can I read here?” Selecting a chapter opens it. Give all five stages these same two actions. Keep the visual warmth by giving sage to the current selection and peach to the resource group. Give public funding, provider prices and family planning questions distinct places within a chapter.

The handbook UI uses Traditional Chinese. The Chinese phrases below are proposed interface copy. This specification updates the home and stage-reading sections of the [existing UI design](UI_DESIGN.md). Its article formats, personal-plan behavior, accessibility and layout limits still apply.

## Where the five stages live

`before_p` means **before pregnancy**. Today it houses the server and frontend, four later stages share one JavaScript object, and all 31 catalog guides carry the historical `preconception` tag. The pregnancy folder already contains a planning checklist. The following is the **proposed workspace layout**. Paths in the first column are relative to the project root. [Current stage definitions](../frontend/web/stages.mjs) · [Existing pregnancy checklist](../after_p/preparation.txt) · [Current catalog](../data_validation/handbook.json)

| Stage-owned entry file | Stable stage ID in links and plans | Content the stage maintains |
| --- | --- | --- |
| `before_p/stage.json` | `preconception` | Planning before pregnancy, including preconception screening and the three existing catalog reading sections. |
| `after_p/stage.json` | `pregnancy` | Prenatal examination coverage, visit preparation and arrangements during pregnancy. The existing checklist supplies leads for collection. |
| `childbirth/stage.json` | `childbirth` | Birth benefits, admission, hospital costs and discharge preparation. |
| `postpartum/stage.json` | `postpartum` | Recovery, postpartum nursing centers, home care and family handover. |
| `childcare/stage.json` | `childcare` | Newborn care through age six, childcare costs and allowances, waiting lists and preschool transitions. |

`frontend/` owns the local server, its public `web/` directory, routes, layout, article and comparison renderers, plan editor and shared tests. `data_validation/` owns the public-data catalog, source evidence, collection and human review. Each stage owns its editorial text, questions, topic order and links to that catalog. A folder name can change without changing a reader's URL or saved question ID. The existing `have/` directory has no role in this layout.

### How the frontend reads a stage

1. The server keeps one ordered registry of the five **stage ID → entry file** pairs above. On `GET /api/handbook`, it reads the five JSON files and calls the existing read-only `snapshot()`. Return the existing response fields with one additive `stages` array in registry order. The frontend uses that array for the selector, chapter readers and question lookup. Keep the static web root at `frontend/web/`. The browser needs no filesystem paths, raw planning documents, database access or extra service.
2. Each entry file declares `id`, `title`, `summary`, `intro`, `chapters` and `topics`. The three chapter keys are `costs`, `health` and `daily`. Each chapter supplies its subtitle and an ordered `entries` list. The shared renderer owns the three navigation labels. Each owned topic has an ID unique within the stage, its canonical chapter key, a title, editorial questions with keys unique within the stage, and an optional `guideId` for published facts. Chapter entries can link to a topic by `stageId` and `topicId`, to a published guide by `guideId`, or to an existing preconception catalog section by `readingSectionIndex` (0, 1 or 2). Where a guide has an editorial preparation sheet, store its copy under `guidePrompts` keyed by the original item ID in one stage file. Keep its rendering logic in the frontend.
3. For example, `postpartum/stage.json` defines the topic `postpartum-care-options` once and places it in its costs chapter. The newborn entry in `childcare/stage.json` uses the following reference.

   ```json
   {"stageId": "postpartum", "topicId": "postpartum-care-options", "label": "新生兒返家前後的照護選擇"}
   ```

   Look up the target topic and its owning chapter, then build the existing stage URL with the parenting reader as its return destination. Each topic has one canonical chapter in its owner's file. Other chapters may link to it. A saved question always uses the owner's `stage_<stageId>_<questionKey>` ID. The same rule lets Pregnancy → Health link to Pregnancy → Costs for `prenatal-coverage`.
4. Build a lookup by original guide ID from the public catalog. Preserve publication checks and regional filtering. The legacy `stage` field describes the existing catalog organization. Use the stage entry's explicit reference to decide where to present a guide. For example, Preconception can link to the childcare allowance guide as a future budgeting concern while Childcare owns its preparation sheet. Both routes open the same item and reviewed records. Pending collection uses a topic with `guideId: null` and the designed gap state.
5. Validate the five IDs, required chapters, unique topic and question keys within each stage, unique preparation-sheet owner per guide and every editorial topic target. A missing file, duplicate owner or dangling editorial reference is a configuration error. Identify the file and key in the server diagnostic and return the existing retryable service error. A valid topic with no reviewed public rows is a successful response with a topic-level gap. If a previously visible public guide is withdrawn, retain the editorial topic and saved question, hide the withdrawn facts and show its gap.

### Migration and compatibility

1. Inventory current routes, guide IDs, question keys and the plan storage key. Split `stageHandbooks` across the four later stage files and give Preconception its own file referencing the existing catalog sections in order. Partition editorial preparation sheets by the decision they support. For example, preconception checkups belong in `before_p/` and childcare allowances in `childcare/`. Preserve catalog IDs and the preconception index entries that link to them. Keep the pregnancy checklist intact. Its estimates or medical timings enter the public UI only through a reviewed record.
2. Assemble the additive response in the shared server. Move active shared frontend code and its tests under `frontend/`, including the native HTML/CSS/JS and the uv project configuration needed to run them. Replace lookups in `home()`, `stagePage()`, `guide()`, `stageReturn()` and `stageQuestion()` with registry, topic or guide lookups. Share the stage reader and keep one stage manifest per owner. Remove the old central stage-content literal once both entry points exercise the new reader.
3. Make `/` the canonical five-stage home, with URLs such as `/?stage=pregnancy#chapters`. Keep `/preconception` as a legacy home entry and `/stages/preconception` as the preconception reader. Preserve the remaining aliases and query/hash rules below. Serve on the same localhost origin and port so existing browser storage remains accessible. Keep the old documented server command working through a thin compatibility launcher in `before_p/server.py`. Document the canonical command, `uv run --project frontend python frontend/server.py --port 8780`. Run each launcher separately during verification. Both must use the same server, frontend files and stage sources.

## What a reader encounters today

On 21 November 2026, the review followed the [local home page](http://localhost:8780/) in fresh Chrome sessions at 390 × 844 and 1440 × 900. All five stage cards selected a stage on the home page and moved focus to its chapter panel. The inconsistency begins **after** that selection.

| Select a stage, then inspect its chapters | What the reader sees | Change the implementer should make |
| --- | --- | --- |
| Preconception · 備孕 | Three in-place chapter links. Selecting health replaces the topic list on home. Opening 健康檢查與用藥 leads to a filterable topic page. Its 備孕手冊 link goes to bare `/preconception`, which defaults to costs. | Use the same chapter-opening action as the other stages. Keep the eight topic indexes one level below it. Return from a topic to the chapter that opened it. [Category index](NAVIGATION_DESIGN.en.md#分類頁改版) |
| Pregnancy · 懷孕 | Three links open a stage reader. Costs opens a question about asking a provider for an itemized bill. Health opens a packing question. Across the three chapters there are zero linked articles. The public-data gap appears below the questions. | Name public prenatal checkup coverage first in costs and make it reachable from prenatal visit preparation. Show its review status where the reader expects the answer. |
| Childbirth · 生產準備 | Costs puts a birth-benefits article above a hospital-estimate question. The second chapter link is called 住院準備清單. A reader cannot identify it by the 健康準備 label used in pregnancy. | Keep the common chapter name visible. Put the admission checklist in its subtitle. Give the birth benefit and the hospital bill separate topic headings. |
| Postpartum · 產後 | Costs links to leave and work support, then asks about paid help at home. There is no named entry for a postpartum nursing center. 家人分工 replaces the third chapter name. | Lead costs with care-setting choices, including 月子中心. Put family handover under the shared daily-life heading. Retain leave and work support. |
| Early parenting · 育兒 0–6 歲 | Costs has two article links, health has none, and daily life has two. Readers can compare allowances and childcare fees and look up preschool transitions. A parent arranging care immediately after discharge has no route here to the postpartum care choices. | Keep the age-specific comparisons. Add a newborn-only handover entry that opens the same postpartum care topic and returns to parenting. |

Two home-page details make the imbalance more pronounced.

- On the default desktop home, Preconception measured 339 px wide and Pregnancy 169 px. Early parenting was peach despite being unselected. At phone width, Preconception occupied a full row. The cause is the permanent `.life-lead` style, the desktop `2fr` first track and the `.life-card:last-child` background rule. Selecting parenting gives it the normal sage current state.
- Even with Pregnancy selected, 政府補助 opens 育兒津貼與托育補助. Its article return link reads 育兒與托育先了解. The shortcut picks the first published guide containing the `allowance` category. The first resource also gets peach and a full row by position. The label promises broader coverage than its destination delivers.

The differences in record depth are real. The [live read-only response](http://localhost:8780/api/handbook) contained 8 topics, 31 guides and 50 reviewed records at inspection. It included preconception checkup records, birth benefits and childcare records. It had no dedicated prenatal checkup coverage or postpartum nursing-center pricing categories among the published guides. The current stage hint switches on the presence of **article links**. A linked leave article therefore changes the hint for the entire postpartum costs chapter, even though it says nothing about the cost of a center. Derive coverage separately for each topic and region.

## Home and chapter navigation

1. **Home.** Show the five stage links in chronological order. Default to Preconception. Activating any link, including the current one, focuses the selected stage's named `#chapters` region. Its panel always has three links in order — 費用與支持, 健康準備, 生活安排. Use a concrete subtitle for each. For Pregnancy, the first link reads “費用與支持 · 產檢公費與補助”. For Childbirth, the second reads “健康準備 · 住院準備清單”. For Postpartum, the third reads “生活安排 · 家人分工”. Indicate the selected stage with an underline and `aria-current` as well as color.
2. **Chapter.** Every chapter link opens `/stages/{stage}?chapter=costs|health|daily`, including the proposed `/stages/preconception` reader. A bare stage URL opens costs. Show a return link to that stage's home panel, a stage heading, the same three chapter links, the chapter heading, then its topics. Each chapter link has a real URL. Switching chapters selects its default content. Inside the preconception reader, populate topics from the existing `reading_sections[0..2].topic_ids` in catalog order. Keep all articles, save actions and existing category URLs reachable.
3. **Resources.** Keep all four shortcuts at equal weight. Rename 政府補助 to 育兒津貼與托育補助 and link by its stable guide ID, `items_095c7855adf6a94c`. It remains available from every home selection. Keep 產前檢查 linked to Pregnancy → Health, with a visible first link to the coverage topic. Label the vaccine shortcut 孕前疫苗紀錄 to match its scope. Keep 準備清單 linked to the personal plan. Public support for each stage belongs inside that stage's costs chapter.
4. **Return and reload.** Preserve the originating stage, chapter, selected topic and expanded question in a validated internal return URL. Also preserve topic filters and page number on an article round trip. The in-page return link and browser Back must let the reader resume the originating list. A shortcut taken from home returns to that home selection. A direct article URL retains its existing catalog fallback. Restore focus to the activating link on return where possible, otherwise to the enclosing chapter heading. A new chapter opens at its heading. Preserve the existing `question=none` and individual question deep links.

**Legacy entry points.** Keep `/`, `/start`, `/explore` and bare `/preconception` as home entries. Interpret old `/preconception?chapter=0|1|2` links without a stage as the corresponding preconception reader (costs, health, daily). With a valid later `stage` on the home URL, render that stage's home panel first, even if a legacy numeric chapter is also present. Retain the numeric chapter as the return preference when switching back to Preconception, marking the matching chapter link in the panel. With `#chapters`, honor the home-panel intent even for a numeric preconception URL. Invalid chapter values fall back to costs on a known stage. Unknown stage paths keep the existing missing-page behavior. Preserve existing topic, item, benefit, article-panel and personal-plan deep links, including stored question IDs.

## What each stage should cover

These are navigation and collection targets. They can ship with an editorial question and an explicit data gap. A topic name alone makes no claim about availability, eligibility or price.

| Stage | Costs and support comes first | Health preparation | Daily life and arrangements |
| --- | --- | --- | --- |
| Preconception | Preserve the catalog's finance, early childcare planning and employment topics. Make the existing preconception checkup support guide reachable with its original geographical scope. | Preserve the four existing health topic groups, including medication and vaccine records. | Preserve partner and household planning. |
| Pregnancy | **產檢公費與補助** first. Then provider fees and optional tests, followed by leave and work support. | Before the packing or clinician questions, link “查看產檢公費與補助” to the same costs topic. Retain preparation, questions and how to obtain results. | Visit transport, accompaniment and work handover. |
| Childbirth | Birth benefits and local birth grants, then hospital stay estimates with room, service and extra charges. | Admission contacts and documents, hospital-supplied and self-supplied items. | Day/night transport, discharge handover and planning the first care setting. |
| Postpartum | **月子中心（產後護理之家）與返家照護** first. Include center, paid home care and family help as distinct choices. Then leave and income support. | Recovery and feeding contacts, care offered at discharge, arrangements for follow-up. | Who takes over after the stay, night care, meals, supplies, transport and backup. |
| Early parenting | Preserve childcare allowances, provider fees and preschool caps by age and care type. For newborn families add “新生兒返家前後的照護選擇” linking to the postpartum topic. | Caregiver health contacts, feeding support and questions for child health visits. | Newborn handover, childcare applications, waiting lists, pickup and backup, later preschool transitions. Keep older-child paths direct. |

Use these addressable entries for the worked paths: `/stages/pregnancy?chapter=costs&topic=prenatal-coverage` and `/stages/postpartum?chapter=costs&topic=postpartum-care-options`. Opening a cross-stage link adds the encoded originating handbook URL as `from`. Accept only known internal handbook routes. Include the topic when synchronizing an opened or closed question to the URL. These topic keys identify editorial content independently of any future public record IDs.

**Two worked reading paths**

- **Pregnancy → Costs.** The first visible topic is 產檢公費與補助. On arrival show central and, when selected, county coverage status above provider costs and questions. With a reviewed record, show the covered examination/service and scope at a glance. Opening it reveals who provides it, documented conditions, exclusions, applicable period and source. Keep optional tests, registration charges and locally documented additions separate. With no records, show “中央產檢公費資料待補” and, for a selected county, “〔縣市〕產檢補助資料待補”. Keep “哪些項目需要另外付費？” available to save. The prenatal shortcut and the health chapter lead to this exact topic in one action from visit preparation.
- **Postpartum → Costs → Care setting.** Show three choices immediately. “月子中心／產後護理之家”, “到宅照護” and “家人協助” each state what the family needs to compare. Center details show the named facility and facility type if documented, location, room and service scope, rate unit, minimum stay, deposit, cancellation and extra charges. Home care uses provider, hours, travel and overtime. Family help uses availability, tasks, expenses to discuss and backup. Do not assume a family member is available or provides free care. Show one choice's details at a time, initially the center. A reader from newborn parenting reaches this same topic, then returns to the newborn entry. A facility price must never imply a countywide rate or an entitlement.
