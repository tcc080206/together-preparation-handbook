# Implementation prompt

Implement the navigation and reading changes for the five-stage 一起準備 handbook in this workspace. The website uses Traditional Chinese. Begin with the two journeys in the design: a reader on the default home page should reach 雙方一般健康檢查 or 每月育兒與托育支出 in two link activations and be able to tell which chapter they are reading.

Read `AGENTS.md`, `frontend/README.md`, `frontend/NAVIGATION_DESIGN.en.md` and `ui_samples.md` before editing. Use the English design's N1–N5 acceptance cases as the delivery checklist. Inspect the existing stage manifests and shared reader first. The shared configuration migration is already complete. [English design](NAVIGATION_DESIGN.en.md)

1. **Reproduce both journeys.** Start at `http://localhost:8780/` with preconception selected. Record the destinations and activation counts. Use a fresh browser profile for any personal-plan checks.
2. **Shorten the routes and preserve the way back.** Add the two named shortcuts inside the corresponding preconception chapters. Open the complete category with all its articles visible and keep compatibility for saved filter and page URLs. Show stage and chapter near the article title. Resolve direct visits and ambiguous placements as specified. On return, restore the list state, originating control and focus. Keep shareable URLs usable after reload.
3. **Support continuation.** Implement the three editorial relationships in the design at their decision points. Resolve published guides and owned topics by stable ID. Preserve context across stages and browser Back. Add named previous/next chapter links after the chapter content for all five stages, using the existing chapter order and the specified boundary behavior.
4. **Implement the six layout cases.** Use the page-layout table to choose components and mobile behavior. In particular, turn the hospital packing sentence into three questions readers can use with their hospital. Align postpartum care options by service hours, scope and billing unit. Reuse the existing questions, record disclosures and save actions. Clearly distinguish an editorial question, a reviewed fact and a missing value.
5. **Work within the shared project.** Use the existing native HTML, CSS, JavaScript and uv setup. Put shared behavior in `frontend/` and stage-specific wording or references in the owning `stage.json`. Preserve the publication gate, national and selected-county states, legacy routes, IDs and saved arrangements. Keep scope to the proposed interface, its editorial references and affected checks. Public-data collection, personal-data migration and deployment are outside the assignment.
6. **Verify the implementation and fix failures.** Follow the applicable checks in `frontend/README.md`. Check what each command reads and writes. Use isolated fixtures for missing, withdrawn and failed data. Exercise keyboard navigation, browser Back, reload and personal-plan compatibility. Capture phone and desktop evidence at 390 × 844 and 1440 × 900 and run the existing eight-viewport layout regression. Exercise both launchers if you change their shared environment or entry points.

Deliver the working changes and a short report with one row for each of N1, N2, N3, N4 and N5. For each row give the actual status, what you exercised, and a route, test result or screenshot that supports it. Include the before/after activation counts for both pilot journeys, affected files, public-data gaps and any remaining limitations. A required case that fails or remains unverified keeps the implementation open.
