# C11-NWT｜新北市生育獎勵金規格

### 目標與範圍
讓使用者一眼知道新北第1名、第2名、第3名以上各可領多少。重新取得執行日適用的官方金額，即使before_p已有三筆也全部抓取。只處理地方現金獎勵，不混中央保險生育給付；此為現金收入，沒有「補助後費用」。

### 固定情境與平台ID

| 情境 | record ID | 必交內容 |
| --- | --- | --- |
| 第1名 | nwt-birth-amounts-first | 金額、每名／每胎／一次性單位、序位與出生日期適用、關鍵戶籍條件 |
| 第2名 | nwt-birth-amounts-second | 同上，不假設同第一名 |
| 第3名以上 | nwt-birth-amounts-third-plus | 同上，以上級距與原表註腳 |

若執行時平台已有同情境，以既有ID優先，MAPPING記錄調整，不能另建重複資料。若現行官方級距改變，交差異與缺口，不能硬塞成舊三列；新增級距另列續卡。

### 來源與需要的條件

從nwt_birth（新北福利申請頁）追民政局／戶政主管機關現行辦法、公告或附表。[來源路線](SOURCE_MAP.md)有完整URL。核對公布日與生效日，未來新制另列。需保留會影響取得或金額的戶籍、出生日期、序位／多胞胎等規定；文件清單、付款進度及一般流程不在首輪必要內容。

### 固定分類設定

```json
{
  "id": "nwt-birth-amounts",
  "title": "新北市生育獎勵金",
  "description": "新北市地方生育獎勵金，第1名、第2名及第3名以上；依現行官方出生日期、序位與戶籍條件。一次性現金給付，不含中央保險生育給付。",
  "order": 40,
  "review_fields": ["金額", "條件", "限制"],
  "field_types": {"金額": "integer", "條件": "text", "限制": "text"}
}
```

分類已存在時複製SQLite設定，不修改既有分類。目標分頁為 `/nwt-birth-amounts`，涵蓋3個情境（前提是執行日官方仍為此三級距）；每次執行均重新盤點，不固定分類順序或假設資料尚未入庫。同時保留before_p三個economic_nwt_birth_*的映射，**但不能只交before_p差異表**。

### 驗收案例

1. before_p有三筆、平台沒有：完整候選3筆，import-ready3筆，不能0筆。
2. 來源可核實：三筆各有數字、單位與來源定位；未知欄位明示缺口，不沿抄舊值當新查證。
3. 平台尚無分類：匯入後左側出現新北市生育獎勵金，可逐筆核對與整頁保存；不替使用者標✅。
4. 重新執行：完整查核仍做，已存在一致資料不再匯入；不影響已保存review。
5. 找不到現行官方依據：工作包標部分完成，不為新增分頁而填舊值或猜值。

依[單卡執行流程](EXECUTION_GUIDE.md)及[交付規格](DELIVERY_SPEC.md)完成查核、去重、驗證與新增匯入；既有資料不覆寫。
